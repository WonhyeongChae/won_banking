# ONE플러스WON | 예비 창업자 시뮬레이션 서비스 수정안

작성일: 2026-10-22
상태: 사용자 설명 기준 수정안. 첨부 초안 본문을 가져오지 못해 기존 내용과 문장별 대조 미수행.
서비스명·주제·보상 정책·데이터 연동은 최종 팀 합의 필요.

## 1. 한 문장 제안

예비 창업자가 창업 위치·사업 규모·업종을 입력하면 예상 매출과 비용, 손익을 시나리오별로 비교하는 리포트를 제공하고, 결과를 이해하는 데 필요한 창업·금융 지식을 학습하면 꿀머니를 적립하는 우리WON뱅킹 연계 서비스 제안.

## 2. 고객과 해결할 문제

핵심 고객은 입지·규모·업종을 고민하는 예비 창업자임. 창업 조건을 바꿨을 때 매출과 운영 부담이 어떻게 달라지는지 비교하고, 결과를 해석하도록 지원하는 것이 목적임.

검증할 문제 가설:
- 상권·임대료·초기 투자 등 정보가 분산돼 동일 기준 비교가 어려움.
- 매출 예상값만으로 임대료·인건비·원가를 감당할 수 있는지 판단하기 어려움.
- 손익분기점·고정비·운영자금 등 개념을 모르면 리포트를 활용하기 어려움.

위 항목은 조사 결과가 아닌 문제 가설임. 예비 창업자 인터뷰와 실제 자료 확인 필요.

## 3. 핵심 기능

### 창업 조건 설정
- 위치: 주소·지도 기반 후보지 또는 상권 선택.
- 업종: 초기에는 데이터 확보 가능한 업종 하나로 제한.
- 규모: 면적, 좌석 수 등 해당 업종에 맞는 기준 사용.
- 운영 조건: 영업일·영업시간·인력·객단가·예산 등을 설정.
- 자동 추정값과 직접 입력값을 구분하고 수정 가능하게 제공.

### 시나리오별 창업 리포트
- 설정 조건 요약과 기준 기간.
- 예상 월매출 범위 및 보수·기준·낙관 시나리오.
- 임대료·인건비·원가 등 주요 비용과 예상 운영손익.
- 손익분기 매출, 초기 투자비, 운영자금 검토 항목.
- 후보 위치·규모·업종 또는 운영 조건 변경 전후 비교.
- 결과에 영향을 주는 변수, 데이터 출처·기준일·추정 가정·누락 비용 표시.

단일 예상값을 확정 매출처럼 표시하지 않음. 매출과 이익을 구분하며, 초기 투자와 월 운영비도 분리함. 데이터 부족 시 신뢰도가 낮은 이유와 추가 입력 항목을 표시함.

### 리포트에 연결된 학습과 꿀머니
- 리포트의 어려운 항목에서 관련 학습으로 바로 이동.
- 예: 손익분기점 해설 → 간단한 문제 → 자신의 조건으로 다시 계산.
- 강의 열람만으로 완료 처리하지 않고 이해도 확인 등 완료 조건 설정.
- 유효한 학습 완료 건에 꿀머니 적립을 제안.
- 동일 콘텐츠 반복 적립 제한, 일·월 한도, 지급 이력과 실패 상태 관리.

꿀머니는 신규 지급 기능을 제안하는 기획임. 기존 지급 정책·사용처·환산율·유효기간을 임의로 확정하지 않음. 지급 연동, 운영 주체, 예산, 중복·부정 적립 방지 정책 확인 필요.

## 4. 대표 이용 흐름

1. 예비 창업자가 후보 위치, 업종, 규모를 선택.
2. 예산과 운영 조건 입력. 출처가 있는 기본값은 수정 가능.
3. 매출·비용·손익을 함께 보여주는 시뮬레이션 리포트 생성.
4. 조건을 바꾸고 후보별 결과와 위험 요인 비교.
5. 이해가 부족한 리포트 항목을 선택해 짧은 학습 수행.
6. 이해도 확인과 완료 조건 충족 후 꿀머니 적립 처리.
7. 배운 내용을 반영해 조건을 수정하고 리포트 재확인.

보상은 학습을 시작하는 유인이고, 서비스의 주된 가치는 창업 조건 비교와 결과 이해임.

## 5. 추정 방식의 기획 원칙

MVP는 검증 가능한 계산식과 데이터 근거 우선 적용. AI 사용 여부는 미정이며, 서비스 핵심에 필수로 가정하지 않음.

업종별 계산 예시 구조:
- 월매출 = 일평균 거래 건수 × 평균 거래 금액 × 월 영업일 수.
- 월 변동비 = 월매출 × 변동비율.
- 월 운영손익 = 월매출 - 월 변동비 - 월 고정비.
- 손익분기 매출 = 월 고정비 ÷ (1 - 변동비율).

위 식은 설명용 단순 모델임. 업종별 조정과 검증 필요. 변동비율이 1 이상이면 위 손익분기 식을 정상 결과로 출력하지 않음. 세금·감가상각·금융비용 등 포함 여부를 리포트에 명시하고, 운영손익을 확정 순이익으로 표현하지 않음.

거래 건수와 객단가를 어떤 자료로 추정할지가 핵심 검증 과제임. 자료가 없으면 사용자가 설정한 가정 기반 계산으로 명시하며 데이터 기반 매출 예측이라고 주장하지 않음. 시나리오 범위도 실제 오차 검증 없이 통계적 신뢰구간으로 표현하지 않음.

## 6. 필요한 데이터와 확인 사항

| 데이터 | 활용 | 확보 전 확인 |
|---|---|---|
| 상권별 업종·매출·점포 정보 | 유사 조건 참고 및 매출 추정 | 제공 범위·이용 조건·최신성·공간 단위 |
| 임대료·면적 | 고정비와 규모 조건 | 실제 계약 차이·보증금·관리비·출처 |
| 인건비·원가·영업 조건 | 비용 계산 | 입력 기준·업종 차이·포함 항목 |
| 초기 투자비 | 예산 검토 | 시설·보증금·재고 등 항목 분리 |
| 학습 콘텐츠·문항 | 결과 해설·이해도 확인 | 내용 검수·저작권·완료 기준 |
| 적립 이력 | 꿀머니 지급 관리 | 연동 가능 여부·지급 정책·한도 |

구체적인 제공 기관이나 API는 아직 검증하지 않음. 후보 자료를 확보한 뒤 evidence.csv에 출처와 제약 기록.

## 7. 최소 구현 범위

지역 하나·업종 하나·핵심 규모 변수로 시작. 조건 입력, 세 가지 시나리오, 후보 비교, 핵심 개념 학습, 적립 상태 화면을 우선 구현.

실제 데이터 미확보 시 가정 기반 데모로 명시. 꿀머니 실제 연동 전에는 모의 적립으로 표시. 실거래·자동 대출 실행·모든 업종 전국 예측은 초기 범위에 포함하지 않음.

## 8. 고객·은행 가치와 검증

고객 가치 가설: 후보 조건 비교와 비용 구조 이해를 도와 창업 준비 의사결정 지원.
은행 가치 가설: 예비 사업자와 조기에 접점을 만들고 창업·금융 학습 참여와 재방문 유도. 상담 연결은 별도 선택 기능으로 검토.

| 검증 항목 | 측정 방법 |
|---|---|
| 리포트 사용성 | 입력 시작 대비 생성 완료율, 후보 비교 수행률 |
| 학습 효과 | 학습 전후 동일 개념 이해도, 학습 완료율 |
| 결과 활용 | 학습 후 조건 재설정률, 사용자 인터뷰 |
| 추정 품질 | 확보 가능한 실제 관측값과 예측 오차·편향 비교 |
| 보상 운영 | 유효 학습당 지급 비용, 중복 적립 차단, 지급 실패율 |

성과 수치는 미설정. 보상 지급 자체를 학습 효과로 해석하지 않음. 실제 매출 검증 자료가 없으면 예측 정확도 입증으로 표현하지 않음.

## 9. 5페이지 제안서 구성

| 페이지 | 핵심 메시지 | 배치할 내용 |
|---|---|---|
| 1 | 창업 전에 조건을 비교하고 배운다 | 한 문장 제안·대상·팀명·선택 주제 |
| 2 | 매출뿐 아니라 비용과 손익의 이해가 필요하다 | 고객 상황·검증된 문제 근거·기존 방식의 한계 |
| 3 | 위치·규모·업종을 바꾸면 리포트도 바뀐다 | 입력 화면·시나리오 비교·추정 근거 |
| 4 | 리포트 해설 학습이 꿀머니 적립으로 이어진다 | 이용 흐름·학습 예시·적립 조건 |
| 5 | 작은 범위에서 예측·학습·보상 운영을 검증한다 | MVP·데이터 조건·고객/은행 가치·지표 |

주제는 ‘우리WON뱅킹 신규 서비스 제안’이 현재 설명과 부합하는 후보임. 팀 최종 확정 필요. AI agent 주제를 택하려면 에이전트의 역할과 행동이 별도로 정의돼야 함.

## 10. 다음 합의 사항

- 초기 대상 업종과 지역.
- 확보 가능한 상권·매출 데이터 및 비용 산정 기준.

- 꿀머니 적립 한도·지급 예산·연동 가능 여부.
- 팀명 표기: 기존 로고 ‘WON 플러스원’과 초안 제목 ‘ONE플러스WON’ 중 확정.

현재 문서는 기획 수정안이며 시장 조사, 매출 예측 검증, 실제 꿀머니 연동이 완료된 상태가 아님.
