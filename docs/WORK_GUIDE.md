# 3인 협업 지침

## 역할과 파일 소유권
| 역할 | 1차 담당 | 주요 산출물 | 검토 |
|---|---|---|---|
| A 기획·근거 | 팀원 이름 미정 | IDEA_BRIEF, evidence.csv, 1~2페이지 원고 | B |
| B 서비스·UX | 팀원 이름 미정 | 이용 흐름·화면, 3~4페이지 원고 | C |
| C 디자인·통합 | 팀원 이름 미정 | DESIGN_SPEC, content.json 통합, 5페이지·PDF | A |

content.json은 C 한 명이 통합. A/B는 storyboard.md의 담당 영역에 제안하고 C에게 전달.
역할은 업무 분담이며 Git 브랜치 보호나 실제 협업 계정 설정을 의미하지 않음.

## 작업 순서
1. 3명 모두 주제 하나·고객 하나·문제 하나 합의
2. A: 현재 앱·고객 불편 근거 확보, B: 해결 흐름 구체화, C: 디자인 기준 정리
3. 주장마다 claims.csv에 근거 ID 연결. 가설은 가설로 표시
4. C가 content.json 통합 후 python scripts/build_pdf.py 실행
5. A는 사실·출처, B는 흐름·설득력, C는 글꼴·넘침·5페이지 여부 검수
6. 최종 파일은 output/pdf/proposal_final.pdf로 복사하고 전원 확인

## 권장 일정 | 2026-10-22 기준 내부 계획
10/22: 주제 확정 → 근거 조사 → 원고·흐름 완성.
10/23: PDF 검수 → 공식 마감 시각 확인 → 여유 있게 접수.
마감 시각은 포스터에 없음. 특정 시각을 임의로 가정하지 않음.

## Git 규칙
브랜치 예: docs/research, docs/ux, docs/deck. 커밋 예: docs: 문제 근거 추가.
원본 이미지는 덮어쓰지 않음. 타인 변경 삭제 금지. 병합 충돌은 담당자와 확인 후 처리.
개인정보·계좌번호·키·실제 고객 거래 원문 저장 금지. 예시 데이터는 synthetic 표시.
